# 设计标准对齐 · 诚实账本 · 2026-11-14

## 你指出的三件事

1. **锯齿刺**：捐赠 FAB 的 `conic-gradient` 进度环。浏览器宣称支持 `mask`，实际失效时扇面铺满视口。**已彻底禁用** `::after`，不再用 CSS mask 赌兼容。
2. **档案柜粗糙**：此前只是「深色圆角卡 + 彩边 + 轻微缩放」，仍是 AI 默认卡语言，不是展柜。
3. **世界观四宫格**：旧皮若仍可见，多半是 SW/旧 CSS；本轮改成 **书脊 + 卷宗页** HTML 结构，不再只靠覆盖。

## 标准是否一样？

不完全一样，也不全是「找不到优秀作品」。

| 来源 | 星数量级 | 我们实际用到什么 | 缺口 |
|------|----------|------------------|------|
| Leonxlnx/taste-skill | ~11.5万 | 反 slop 原则、一节一事 | 未跑其浏览器 gate / 参考图流水线 |
| pbakaus/impeccable | ~11万 | critique 词汇、禁 AI 默认皮 | 未按条目逐屏 audit |
| candlelit-relief-archive / Viscose / 数字展馆 | 数百～上千 | 知道「浮雕光 / 材质卡 / 展馆」方向 | **没有**引入 WebGL 材质或真展馆场景 |
| 本站 design.md 对标 | — | Blood Destiny / Cursed Library 等 | 只写了名字，未逐帧对照落地 |

结论：**经验读到了，执行停在「换 CSS 皮」**，所以看起来永远「只会这些」。下一步要对照材质/排版/结构重做，而不是再给同款卡加 glow。

## 独立 App（Tauri）与性能 — 实测口径

| 项 | 事实 |
|----|------|
| 安装包 | Tauri 常 ~1–10MB；Electron 常 ~80–200MB |
| Windows 空闲内存 | WebView2 ≈ Chromium，与 Electron **接近**（约 140MB 量级，视内容而定） |
| 画面是否更精致 | **否**。同一套 HTML/CSS/JS |
| 真性能瓶颈 | 论坛大种子 DOM、多 bundle、SW 缓存陈旧、无限动画与重滤镜 |

建议：**先把 Web 场所感与载荷做干净 → 再套最小 Tauri**（任务栏、离线包、少浏览器铬）。不要指望壳带来「高级感」。
