### 2.2 品牌性格维度对比矩阵（12 维）

| 性格维度 | 飞行雪绒 | 星炬学院 | 设计映射 |
|----------|----------|----------|----------|
| **温度** | 温暖／偏热 | 冷静／偏凉 | 色彩色相：OKLCH 350° vs 250° |
| **距离感** | 亲密／第一人称 | 权威／第三人称 | 字距：紧排/松排；人称：我/我们 vs 学院/读者 |
| **节奏** | 慢／呼吸感 | 快／效率感 | 动效时长：520ms vs 240ms；缓动：回弹 vs 干脆 |
| **叙事方式** | 抒情／意识流 | 考据／结构化 | 布局：瀑布/时间线 vs 索引/卡片 |
| **物理隐喻** | 夜电台 / 录音带 / 粉雪 | 档案柜 / 通行证 / 星象图 | 装饰元素：磁带卷轴 vs 装订线/印章 |

| **信息密度** | 低／留白多／让人停留 | 中高／信息完整／让人查阅 | 间距：space-8 常用 vs space-6 常用 |
| **色彩策略** | 单色相+多明度（粉→白→冰） | 双色相+强对比（蓝+金） | 色板：主色占90% vs 主85%金15% |
| **信任构建** | 情感共鸣（真诚/脆弱/真实） | 证据展示（来源分级/考据链/编号） | UI签名：频率脉冲 vs 印章编号 |

### 2.4 「防止二次呆板」设计策略

过度反 AI 味可能导致设计陷入「刻意手工感 → 另一种公式化呆板」。本项目采用 5 层防护：

| 层级 | 策略 | 执行方法 |
|------|------|----------|
| L1 **随机度阈值** | 瑕疵/随机化设置上下限 | 雪花残缺率 10-20%；边框偏移 ≤1px；标签旋转 ≤5°。超过阈值的效果在 code review 时打回 |
| L2 **用户控制开关** | 可关闭「手工感增强」 | 设置面板增加 `「质感增强」开关`（藏于主题切换三级菜单），关闭后所有瑕疵/随机化清零，回归干净 UI |
| L3 **内容驱动形变** | 瑕疵形态由内容内容决定而非随机 seed | 帖子长度决定装订孔位置；标签数量决定索引标签切角角度 → 不是「为了瑕疵而瑕疵」 |
| L4 **季节性演化** | 瑕疵/风格按月缓慢变化 | 8月：雪花偏完整/装订偏新；12月：雪花偏残缺/装订偏磨损 → 避免公式化永久固化 |
| L5 **A/B 结构变体** | 同一组件提供 2-3 种结构变体 | Hero 区：A 布局(频率条居中) / B 布局(频率条左下) / C 布局(无频率条，用磁带卷轴)；按 UA hash 分发，收集点击率反馈 |

### 9.2 设计决策日志条目格式（强制执行）

```markdown
## DD-001: 飞行雪绒 Hero 标题字距非均匀化
- **日期**: 2026-08-XX
- **关联任务**: P0-2
- **问题**: Hero 标题四字「飞行雪绒」均匀字距（AI 默认）导致品牌签名感不足
- **备选方案**:
  A: 均匀字距（默认）— 优点：安全、对齐易 缺点：AI 味重、无个性
  B: 非均匀字距（飞-行紧 / 雪-绒松）— 优点：手工感强、签名级 缺点：实现略复杂、移动端需调优
  C: 单行 SVG path 文字（最强定制）— 优点：完全可控 缺点：无障碍差、复制粘贴失效
- **决策**: 方案 B（非均匀字距 clamp 响应式）
- **理由**: ① S4 专属武器 ② 可访问性保持不变 ③ 移动端用 media query 回退均匀字距防溢出
- **实现细节**: `.hero-title-mark { letter-spacing: 0.4em 0.1em 0.5em 0.1em; /* 飞 行 雪 绒 */ }` 用 nth-child 单独设置每个字
- **验证截图**: handoff/screenshots-v11/DD-001.png
```

### 10.2 新内容/新组件扩展指引

#### A. 新增一个页面组件的 10 步流程

```
Step 1: 品牌定位 → 该组件属于「雪绒侧」还是「学院侧」？（通常二选一，跨侧需双实现）

Step 5: 写 DOM 结构 → 参考 COMPONENT-SPEC-v11.md 同类组件模板
Step 6: 写 CSS → 移动端-first（≤480px 先写对），再加断点扩展

Step 8: WCAG 检查 → axe-core 局部扫描 + 键盘可达性检查
Step 9: 决策日志 → 新增 DD-XXX 条目，解释该组件的设计选择
Step 10: 回归测试 → smoke-check + 截图入库
```

#### B. 新增一个角色页面的快速流程（复用模板）

```
Step 1: 复制 characters/_template/index.html（新建时创建模板）
Step 2: 替换角色专属色 data-char="newchar" + tokens 变量扩展
Step 3: 选择角色专属氛围（从 14 种氛围模板中选 1 种：雪/水/森/钢/月/书/星/火/冰/雷/风/土/光/暗）

Step 5: 模块 summary 替换为角色专属图标
Step 6: 角色切换导航补新链接
Step 7: 构建 + smoke-check
```

### 10.3 常见问题与维护陷阱（FAQ & Anti-Pitfalls）

从 project_memory.md Lessons Learned 延伸：

| 常见陷阱 | 触发条件 | 预防措施 | 修复方案 |
|----------|----------|----------|----------|
| **SyncManager 裸函数传参** | 新代码调用 `connectSubmissions(fn, fn)` 而非对象 | 代码 grep `connectSubmissions(` 时 lint 规则警告；ESM 导出时参数类型断言 | 立即改为 `{ onNewSubmission, onUpdateSubmission }` 对象传参 |
| **新模块新建 supabase 客户端** | 新组件内 `createClient` 再次调用 | lint 规则禁止出现 `createClient(`（除 supabase-adapter.js） | 改为消费 `window.supabaseClient`（并加 typeof 守护） |
| **DataRepository.delete_token 丢失** | 新评论接口不加 delete_token 链 | 单元级 grep：新增 addComment 调用处必须传 extraFields | 从调用处到 repository.js 全链路补传 delete_token |
| **新模块无 typeof 守护** | 页面模块未加载时，新 JS 直接引用变量报错 | 模板新 JS 首行：`if (typeof X === 'undefined') return` 样板 | 在每个跨文件引用处加 typeof 守护 |
| **社区评论事件委托混用** | 新 comment 点击同时绑 `data-community-target` 和 `data-target-id` | 两套事件委托分文件（主站/论坛）写死各自选择器 | 分文件修正选择器：社区只用 community-target / 博客只用 target-id |
| **标签筛选 OR 语义误用** | 新筛选 UI 写 `activeTags.some(...)` | Code Review 时 grep `.some(` 出现在标签筛选 → 打回 | 统一改为 `activeTags.every(...)` 语义 |
| **设计令牌硬编码回潮** | 新组件 CSS 直接写 `#e879a8` / `#6d8fd6` | 自定义 lint 脚本：每 commit 前 grep hex → 有则报错（仅允许注释 hex） | 改为引用 tokens-*.css 变量；若变量缺失先补 TOKENS-AUTHORITY-v11.md |
| **两站组件结构镜像** | 新组件同时出现在两站 → 复制粘贴换色 | Code Review Checklist：两站同功能组件 DOM class 重合率 ≤30% | 重新设计另一侧组件结构（雪绒用 Letter/学院用 Ecosystem） |
